로컬 PostgreSQL과 Backend 연결

이번 주에는 실제로 실행합니다. Database를 설치하고 사용자 세 명을 저장합니다. FastAPI에서 저장된 사용자 목록과 한 명의 정보를 읽습니다.

완성할 흐름: HTTP request → main.py → database.py의 연결 함수 → PostgreSQL 조회 → JSON response.

main.py는 API 요청과 응답을 처리합니다. database.py는 DB 연결을 관리합니다. seed.py는 연습용 데이터를 넣습니다. SQL과 설정도 별도 파일로 둡니다. 로그인은 이후 주차에서 구현합니다. 이번에는 로그인에 필요한 비밀번호 저장 형태까지 준비합니다.

1. Backend 설계자가 먼저 정할 것

Database는 데이터를 저장하고 조회하는 시스템입니다. PostgreSQL은 이번에 사용할 database 관리 소프트웨어입니다. SQL은 database에 조회나 변경을 요청하는 언어입니다. PostgreSQL을 설치하고, SQL로 데이터를 다룹니다.

Table은 같은 종류의 데이터를 행과 열로 정리한 구조입니다. Row는 한 건의 데이터입니다. Column은 각 row에 포함되는 항목입니다. Users table에서는 사용자 한 명이 row이고, 이름이 name column입니다.

설계 질문이번 실습의 결정
무엇을 저장하는가?사용자 한 명의 식별값, 이름, email, 비밀번호 hash
사용자를 어떻게 구별하는가?바뀔 수 있는 이름 대신 고유한 id 사용
빠지거나 중복되면 안 되는 값은?네 항목 모두 필수. Email 중복 금지
누가 어떤 값을 정하는가?DB가 id를 생성. 프로그램이 비밀번호 hash를 생성
어떤 조회를 제공하는가?최대 100명 목록과 id로 한 명 조회
응답에 무엇을 공개하는가?이 로컬 실습에서는 id, name, email만 공개

Persistence는 프로그램을 종료해도 저장된 데이터가 남는 성질입니다. main.py 안의 Python 목록은 실행이 끝나면 사라집니다. PostgreSQL에 저장을 확정한 데이터는 API server를 재시작해도 남습니다.

Constraint는 DB가 데이터에 적용하는 규칙입니다. 예를 들어 중복 email을 거절하도록 만들 수 있습니다. API가 입력을 검사하더라도, 다른 프로그램에서 DB를 수정할 수 있습니다. 그래서 중요한 규칙은 DB에서도 검사합니다.

이번 목표는 한 table의 저장과 조회입니다. Table 사이의 관계, 빠른 조회를 위한 index, 여러 변경을 함께 처리하는 transaction은 이후 주차에서 확장합니다.

2. Users table의 네 column

Column종류와 역할규칙
idbigint: 큰 범위의 정수. 사용자 식별값DB가 자동 생성. Primary key
nametext: 글자로 된 값앞뒤 공백을 제외한 길이 1~50
emailtext: email 주소필수, 중복 금지, 소문자로 저장
password_hashtext: 비밀번호 검증에 사용할 hash필수. 조회 응답에는 제외

Primary key는 row를 고유하게 식별하는 값입니다. 값이 없거나 중복되면 안 됩니다. 자동으로 증가하는 id에는 빈 번호가 생길 수 있습니다. Id를 사용자 수로 해석하면 안 됩니다.

Hash는 비밀번호를 검증할 수 있도록 변환한 결과입니다. 비밀번호 원문을 복원하는 방식으로 사용하지 않습니다. 나중에 로그인하면 입력한 비밀번호가 저장된 hash와 맞는지 검증합니다.

사용자에게 받는 입력 이름은 password가 될 수 있습니다. 하지만 저장 column은 password_hash로 구분합니다. 이번 실습은 Argon2를 사용하는 라이브러리로 hash를 만듭니다. Argon2는 비밀번호 저장을 위한 hash 방식입니다. Hash 방식 자체를 직접 구현하지 않습니다.

또 하나 구분해야 합니다. DB 접속 비밀번호는 Python 프로그램이 PostgreSQL에 연결할 때 사용하는 값입니다. 사용자 비밀번호는 나중에 서비스 로그인에 사용할 값입니다. 서로 다른 용도입니다.

비밀번호 hash 도구: FastAPI 공식 보안 예제.

확인: name을 primary key로 쓰면 어떤 문제가 생길까요?

동명이인이 있을 수 있습니다. 이름도 바뀔 수 있습니다. 사용자를 계속 식별하기 위해 이름과 별도의 id를 사용합니다.

3. PostgreSQL 설치와 접속

설치는 운영체제에 맞게 한 가지 방법만 선택합니다. 이미 PostgreSQL이 실행 중이면 기존 설치를 사용합니다. 같은 port에 두 PostgreSQL server를 실행하지 않습니다. Port는 컴퓨터에서 통신 접점을 구별하는 번호입니다. 이번 실습의 DB port는 5432입니다.

macOS 설치 — Postgres.app

Mac에서는 Postgres.app으로 진행합니다. PostgreSQL server와 접속 도구가 함께 들어 있습니다. Homebrew 설치는 필요하지 않습니다.

① 다운로드

  1. Mac용 Postgres.app 다운로드 페이지를 엽니다.
  2. Latest Release의 안정 버전을 선택합니다. Beta 또는 RC는 이번 실습에서 사용하지 않습니다.
  3. Universal 표시는 Apple Silicon Mac과 Intel Mac에서 사용할 수 있다는 뜻입니다. 다운로드 페이지의 macOS 요구 버전도 확인합니다.

② 설치와 실행

  1. 내려받은 파일을 엽니다.
  2. Postgres 앱을 Applications(응용 프로그램) 폴더로 옮깁니다.
  3. Applications에서 Postgres 앱을 실행합니다.
  4. 처음 설치했다면 Initialize를 누릅니다. DB 파일과 기본 구성을 준비하는 단계입니다.
  5. Server가 실행 중인지 확인합니다. 기본 port는 5432입니다.

이미 설치했다면 다시 초기화하지 않고 기존 실행 상태를 확인합니다. Port 사용 중 오류가 나오면 다른 PostgreSQL이 실행 중인지 확인합니다.

③ 터미널에서 접속

Terminal 앱을 엽니다. psql은 SQL을 입력하여 PostgreSQL과 통신하는 도구입니다. 다음 명령은 앱에 포함된 psql을 실행하여 postgres database에 접속합니다.

"/Applications/Postgres.app/Contents/Versions/latest/bin/psql" -d postgres

기본 설정에서는 Mac 사용자 이름에 해당하는 DB role로 접속합니다. 별도 계정을 설정했다면 해당 계정을 사용하세요. 접속 후 나타나는 postgres=# 같은 표시는 SQL을 입력할 수 있다는 뜻입니다.

psql 안에서 다음 명령을 실행합니다. 현재 연결 정보를 확인하는 명령입니다.

\conninfo
SELECT current_database(), current_user;
\q

SELECT 결과에서 database가 postgres인지 확인합니다. current_user는 연결한 DB role입니다. \q는 DB server를 끄는 명령이 아니라 psql 접속을 종료하는 명령입니다.

④ 이후 명령을 psql로 짧게 실행하기

PATH는 터미널이 실행 도구를 찾는 폴더 목록입니다. 아래 명령을 터미널에서 실행하면 현재 터미널에서 psql을 짧게 호출할 수 있습니다.

export PATH="/Applications/Postgres.app/Contents/Versions/latest/bin:$PATH"
psql --version

이 설정은 현재 터미널에 적용됩니다. 새 터미널에서는 다시 실행하거나 psql의 전체 경로를 사용하세요. Version 출력은 접속 도구 설치를 확인합니다. DB 실행 여부는 위의 실제 접속으로 확인합니다.

설치 확인이 끝나면 Windows 설치 부분을 건너뛰고 4절: Database와 users table 만들기로 이동합니다. Postgres.app의 기본 로컬 접속은 비밀번호 검증 없이 허용될 수 있습니다. 이후 role에 비밀번호를 정하는 것과 server가 비밀번호 검증을 요구하도록 설정하는 것은 별개의 작업입니다.

설치 근거: Postgres.app 공식 설치 안내.

Windows

  1. PostgreSQL 공식 Windows 다운로드 안내에서 installer를 받습니다.
  2. PostgreSQL server와 command line tools를 설치합니다.
  3. 설치 중 관리자 postgres의 비밀번호를 정합니다. Port는 비어 있다면 5432를 사용합니다.
  4. 설치된 SQL Shell (psql)을 엽니다. Server는 localhost, database는 postgres, 사용자 이름은 postgres로 접속합니다.

이후 터미널에서 psql이 인식되지 않으면 PostgreSQL 설치 폴더의 bin 경로를 사용하거나 SQL Shell에서 접속합니다. Python 실행 명령은 프로젝트 터미널에서 실행합니다.

설치 근거: PostgreSQL 다운로드, Postgres.app 문서.

4. Database와 users table 만들기

명령을 입력할 위치를 구분하세요. 터미널에서는 psql이나 uv를 실행합니다. psql 안에서는 SQL을 실행합니다. SQL 끝의 세미콜론은 명령이 끝났다는 표시입니다. 역슬래시로 시작하는 명령은 psql 전용 명령입니다.

Role은 PostgreSQL에서 권한을 부여하는 대상입니다. LOGIN을 허용한 role로 접속할 수 있습니다. 관리자 대신 실습 전용 role을 만들고, 실습 DB의 소유자로 지정합니다. DB 이름은 이후 주차에도 사용할 study_db로 통일합니다. Role 이름과 비밀번호는 각자 정합니다. 아래 your_role은 예시 자리이므로 모두 본인이 정한 같은 이름으로 바꾸세요. 예를 들어 jude_dev를 사용할 수 있습니다. 이번 실습에서는 이름을 영문 소문자로 시작하고 영문 소문자·숫자·밑줄만 사용하세요. 다음 명령은 최초 한 번만 관리자 psql에서 실행합니다.

CREATE ROLE your_role LOGIN;
\password your_role
CREATE DATABASE study_db OWNER your_role;
\q

\password가 비밀번호를 두 번 묻습니다. 각자 정한 DB 접속 비밀번호를 입력하세요. 비밀번호를 SQL 문장에 직접 적지 않습니다. 입력한 글자가 표시되지 않는 것은 정상입니다. CREATE DATABASE는 비어 있는 study_db를 만듭니다. 이후 주차에는 같은 database를 계속 사용하므로 다시 만들지 않습니다. OWNER 뒤에도 본인이 정한 role 이름을 넣습니다. \q는 psql을 종료합니다.

이제 터미널에서 실습 계정으로 다시 접속합니다. -h는 서버 주소, -p는 port, -U는 role, -d는 database, -W는 비밀번호 입력 요청입니다.

psql -h 127.0.0.1 -p 5432 -U your_role -d study_db -W

psql 안에서 다음 SQL을 실행합니다. 이미 users table을 만들었다면 반복 실행하지 말고 \d users로 구조를 확인하세요.

CREATE TABLE users (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name text NOT NULL CHECK (char_length(btrim(name)) BETWEEN 1 AND 50),
    email text NOT NULL UNIQUE CHECK (email = lower(email)),
    password_hash text NOT NULL
);
  • CREATE TABLE users: users라는 table을 만듭니다.
  • GENERATED ALWAYS AS IDENTITY: 새 row의 id를 DB가 생성합니다.
  • NOT NULL: 값이 빠진 상태를 허용하지 않습니다. 빈 문자열까지 막는 것은 아닙니다.
  • UNIQUE: 같은 email이 두 번 저장되는 것을 막습니다.
  • CHECK: 괄호 안의 조건을 검사합니다.
  • btrim(name): 검사할 때 이름의 앞뒤 공백을 제거합니다. 저장한 원문을 바꾸지는 않습니다.
  • char_length: 글자 수를 셉니다. BETWEEN 1 AND 50은 1부터 50까지를 허용합니다.
  • lower(email): email을 소문자로 바꿉니다. 원래 값과 같은지 검사하여 소문자 저장 정책을 적용합니다.

Email의 소문자 정책은 이번 수업의 선택입니다. CHECK는 email 형식 전체를 검증하지 않습니다. 형식 검사는 다음 주 API 입력 검증에서 추가합니다.

\d users
SELECT id, name, email FROM users;

아직 row를 넣지 않았으므로 조회 결과는 0개입니다. Column을 만든 것과 사용자 데이터를 넣은 것은 다른 작업입니다.

구조와 제약: PostgreSQL constraints.

5. 프로젝트에서 파일 직접 만들기

별도 실습 파일은 받지 않습니다. 기존 수업 프로젝트를 편집기에서 열고, 아래 순서대로 파일을 작성합니다. 프로젝트 폴더는 pyproject.toml이 있는 폴더입니다. 터미널의 설치·실행 명령은 이 폴더에서 입력합니다.

① 필요한 라이브러리 설치

Driver는 Python에서 database와 통신하게 해 주는 라이브러리입니다. 이번에는 psycopg를 사용합니다. python-dotenv는 파일에 적힌 연결 설정을 읽습니다. pwdlib는 비밀번호 hash를 만듭니다. uv add는 필요한 라이브러리를 설치하고 pyproject.toml에 기록합니다.

uv add "psycopg[binary]" python-dotenv "pwdlib[argon2]"

이전 주차에서 설치한 FastAPI와 uv를 그대로 사용합니다. pyproject.toml이 보이지 않으면 새로 만들기 전에 기존 프로젝트 폴더를 열었는지 확인하세요.

② 파일 위치 정하기

아래 기본 구조는 main.py가 프로젝트 폴더에 있는 경우입니다. database.py와 seed.py는 main.py와 같은 폴더에 새로 만듭니다. .env.local도 database.py와 같은 폴더에 만듭니다.

프로젝트 폴더/
  pyproject.toml       ← 기존 파일, uv add가 갱신
  uv.lock             ← uv가 관리
  main.py             ← API 코드
  database.py         ← 새로 작성: DB 연결
  seed.py             ← 새로 작성: 연습 데이터 입력
  schema.sql          ← 4절의 CREATE TABLE SQL 기록
  .env.local          ← 각자의 실제 연결 설정
  .env.example        ← 비밀번호가 없는 설정 예시
  .gitignore          ← Git에 올리지 않을 파일 목록

schema.sql에는 4절의 CREATE TABLE 문을 그대로 저장합니다. 이 파일을 저장하는 것만으로 table이 만들어지지는 않습니다. 4절에서 psql로 SQL을 실행했다면 다시 실행하지 않습니다.

기존 main.py가 app 폴더 안에 있다면

기존 파일을 옮길 필요는 없습니다. app/database.py, app/seed.py, app/.env.local을 만듭니다. Python 파일의 import는 아래 기본 예제 대신 from app.database import connect_db로 작성합니다. 프로젝트 폴더에서 seed는 uv run python -m app.seed, API는 uv run fastapi dev app/main.py로 실행합니다. -m app.seed는 app 폴더의 seed를 Python module로 실행한다는 뜻입니다. App 폴더에 __init__.py가 없다면 빈 파일로 추가합니다.

③ 연결 설정 작성

Environment variable은 코드 밖에서 전달하는 설정값입니다. 먼저 .env.example을 만들고 다음 내용을 적습니다. 예시 파일에는 실제 비밀번호를 넣지 않습니다.

PGHOST=127.0.0.1
PGPORT=5432
PGDATABASE=study_db
PGUSER=your_role
PGPASSWORD=replace_with_your_database_role_password

편집기에서 이 파일을 복사하여 같은 폴더에 .env.local을 만듭니다. .env.local의 PGUSER에는 4절에서 만든 role 이름을 적습니다. PGPASSWORD에는 각자 정한 DB 비밀번호를 적습니다. PGDATABASE는 study_db를 유지합니다.

PGHOST는 DB 주소이고 PGPORT는 접속 port입니다. PGPASSWORD는 서비스 사용자의 비밀번호가 아닙니다. 비밀번호에 # 같은 문자가 있다면 dotenv 파일에서 값을 따옴표로 감싸세요.

④ .gitignore에 추가

기존 .gitignore의 내용을 유지하고, 아래 항목이 없다면 추가합니다. .gitignore는 Git이 새 파일을 추적하지 않도록 정하는 파일입니다. 이미 Git에 올린 비밀번호 파일을 숨겨 주지는 않습니다.

.env.local
.venv/
__pycache__/

실제 비밀번호를 넣은 .env.local은 개인 컴퓨터에만 둡니다. .env.example은 설정 안내로 공유합니다. 이제 6절에서 세 Python 파일을 작성한 뒤 7절에서 데이터를 넣습니다.

6. 역할별 파일 분리와 DB 연결

Separation of concerns는 서로 다른 역할의 코드를 나누는 원칙입니다. 파일 수를 늘리는 것이 목적은 아닙니다. 어떤 설정이나 기능을 바꿀 때 어디를 수정할지 분명하게 만듭니다.

파일역할수정하는 상황
database.py연결 설정 읽기와 DB 연결 생성연결 대기 시간이나 연결 방식 변경
main.pyHTTP 입력, 조회 SQL, 응답 처리Endpoint나 응답 형태 변경
seed.pyDummy data 생성과 저장연습용 사용자 추가
.env.local각자의 DB 접속 설정Role 이름이나 비밀번호 변경
schema.sqlTable 구조 정의Column과 constraint 설계 변경

main.py와 seed.py가 각각 DB 연결 코드를 갖고 있으면 연결 정책을 두 곳에서 고쳐야 합니다. database.py의 같은 함수를 가져오면 한 곳에서 관리할 수 있습니다. API server 실행과 dummy data 입력도 별도 명령으로 구분됩니다.

Import는 다른 파일에 정의된 기능을 가져오는 문법입니다. from database import connect_db는 같은 폴더의 database.py에서 connect_db 함수를 가져옵니다. Import한 것만으로 DB 연결이 만들어지지는 않습니다. 함수 안의 psycopg.connect는 connect_db()를 호출할 때 실행됩니다.

편집기에서 아래 파일 이름을 확인하고 각 코드 블록을 해당 파일에 작성합니다. 기존 main.py의 app = FastAPI()는 중복해서 만들지 않습니다. 기존 경로와 새 /users 경로가 중복되지 않도록 확인하세요. 아래 main.py는 이번 조회 기능에 필요한 전체 예시입니다.

① database.py — 연결을 만드는 공통 함수

import os
from pathlib import Path

import psycopg
from dotenv import load_dotenv
from psycopg.rows import dict_row

load_dotenv(Path(__file__).with_name('.env.local'))


def connect_db():
    if not os.getenv('PGDATABASE') or not os.getenv('PGUSER'):
        raise RuntimeError('Set PGDATABASE and PGUSER in .env.local')
    return psycopg.connect(connect_timeout=5, row_factory=dict_row)

② main.py — 연결 함수를 가져와 API에서 사용

from fastapi import FastAPI, HTTPException, Query

from database import connect_db

app = FastAPI(title='Week 06: Local PostgreSQL')


@app.get('/users')
def list_users(limit: int = Query(default=20, ge=1, le=100)):
    with connect_db() as conn:
        rows = conn.execute(
            'SELECT id, name, email FROM users ORDER BY id LIMIT %s',
            (limit,),
        ).fetchall()
    return {'items': rows}


@app.get('/users/{user_id}')
def get_user(user_id: int):
    with connect_db() as conn:
        user = conn.execute(
            'SELECT id, name, email FROM users WHERE id = %s',
            (user_id,),
        ).fetchone()
    if user is None:
        raise HTTPException(status_code=404, detail='User not found')
    return user

③ seed.py — 필요할 때만 연습 데이터 입력

from getpass import getpass

from pwdlib import PasswordHash

from database import connect_db


def seed_users():
    password = getpass('Choose a dummy password (12+ characters): ')
    if len(password) < 12:
        raise ValueError('Use at least 12 characters for this exercise')
    hasher = PasswordHash.recommended()
    with connect_db() as conn:
        for name, email in [('Ada', 'ada@example.com'),
                            ('Lin', 'lin@example.com'),
                            ('Grace', 'grace@example.com')]:
            conn.execute(
                '''INSERT INTO users (name, email, password_hash)
                   VALUES (%s, %s, %s)
                   ON CONFLICT (email) DO NOTHING''',
                (name, email, hasher.hash(password)),
            )
    print('Dummy users are ready. Existing emails were left unchanged.')


if __name__ == '__main__':
    seed_users()

if __name__ == '__main__'은 이 파일을 직접 실행했을 때만 아래 함수를 호출하는 조건입니다. 따라서 uv run python seed.py로 데이터를 넣고, uv run fastapi dev main.py로 API를 켭니다. API를 켤 때마다 seed를 실행하지 않습니다.

Import 방향은 main.py → database.py, seed.py → database.py입니다. Database.py는 main.py를 가져오지 않습니다. 연결 코드가 API 앱에 의존하지 않으므로 seed에서도 재사용할 수 있습니다.

연결 부분부터 읽기

  1. load_dotenv는 database.py 옆의 .env.local을 읽습니다. 이미 설정된 environment variable이 있으면 기본적으로 그 값을 유지합니다.
  2. connect_db는 DB 연결을 만드는 함수입니다. PGDATABASE와 PGUSER가 없으면 먼저 설정 오류를 알립니다.
  3. psycopg.connect는 PGHOST 등 PG 설정을 사용합니다. connect_timeout=5는 연결 대기 시간을 5초로 제한합니다.
  4. dict_row는 조회한 row를 column 이름과 값의 묶음으로 받게 합니다.
  5. with 블록은 작업이 끝나면 연결을 닫습니다. Seed가 정상 종료되면 저장을 확정하고, 중간에 실패하면 해당 작업의 변경을 취소합니다.

목록 조회 읽기

@app.get('/users')는 GET /users를 list_users 함수에 연결합니다. Query는 주소의 물음표 뒤에 넣는 입력입니다. limit은 기본 20, 최소 1, 최대 100으로 제한합니다. SELECT에서 password_hash를 선택하지 않습니다.

execute는 SQL을 DB에 전달합니다. fetchall은 결과 row들을 가져옵니다. 반환한 items를 FastAPI가 JSON으로 응답합니다. 사용자가 없으면 items는 빈 목록입니다.

한 명 조회 읽기

user_id: int는 path의 값을 정수로 받겠다는 뜻입니다. WHERE id = %s는 id가 입력값과 같은 row를 찾습니다. %s는 입력값을 별도로 전달할 자리입니다. (user_id,)는 값 하나를 담은 Python tuple입니다. 여기서 쉼표는 값 하나짜리 tuple을 만들기 위해 필요합니다.

입력값을 SQL 문자열에 직접 붙이지 않습니다. Psycopg에 SQL과 값을 따로 전달합니다. fetchone은 한 row를 가져오고, 결과가 없으면 None을 돌려줍니다. None이면 HTTPException으로 404 응답을 보냅니다.

이번 DB driver 호출은 동기 방식이므로 조회 함수는 일반 def를 사용합니다. 요청마다 연결을 여는 작은 실습입니다. 연결을 재사용하는 pool은 후속 주차에서 다룹니다. 조회 SQL은 현재 main.py에 두고, API가 늘어나면 데이터 조회 역할도 별도 파일로 분리할 수 있습니다.

연결과 query 처리: Psycopg basic usage.

7. Dummy data 세 명 저장하기

Dummy data는 기능 확인용 연습 데이터입니다. Seed는 초기 연습 데이터를 넣는 작업을 뜻합니다. 이번 예제는 seed.py의 seed_users 함수로 Ada, Lin, Grace를 넣습니다.

6절에서 작성한 세 Python 파일과 .env.local을 저장했는지 확인합니다. 기본 구조에서는 프로젝트 폴더에서 다음 명령을 실행합니다. app 폴더 구조라면 5절의 실행 명령을 사용합니다.

uv run python seed.py

연습용 사용자 비밀번호를 12글자 이상 입력합니다. 이 길이는 이번 실습의 입력 규칙입니다. 실제로 사용하는 비밀번호는 입력하지 마세요. 세 연습 계정에 같은 입력값을 사용하지만, 라이브러리가 각 hash 생성에 무작위 값을 사용하므로 저장 결과는 달라질 수 있습니다.

이 명령은 API server를 켜지 않고 seed 작업만 수행합니다. 코드는 각 비밀번호를 hash로 바꾼 뒤 INSERT로 저장합니다. INSERT는 row를 추가하는 SQL입니다. 같은 email이 이미 있으면 ON CONFLICT로 건너뜁니다. 재실행해도 기존 비밀번호나 이름을 덮어쓰지 않습니다.

psql로 다시 접속하여 확인합니다. SELECT는 읽을 column, FROM은 table, ORDER BY는 정렬 기준을 정합니다.

SELECT id, name, email FROM users ORDER BY id;
SELECT count(*) FROM users;

새로 만든 빈 table에 seed를 한 번 실행했다면 세 명이 나옵니다. count(*)는 row 수를 셉니다. id는 항상 1부터 연속이라고 가정하지 말고 실제 출력값을 확인하세요.

8. 실제로 실행하고 확인하기

프로젝트 폴더에서 API server를 실행합니다. 아래는 main.py가 프로젝트 폴더에 있는 경우입니다. 이 터미널을 실행 상태로 두세요.

uv run fastapi dev main.py

새 터미널에서 curl로 요청합니다. curl은 HTTP 요청을 보내는 도구입니다. -i는 응답 header와 body를 함께 표시합니다. Windows PowerShell에서는 curl 대신 curl.exe를 사용합니다.

curl -i "http://127.0.0.1:8000/users?limit=2"
curl -i http://127.0.0.1:8000/users/1

두 번째 명령의 1은 실제 목록에 나온 id로 바꾸세요. 목록은 200과 최대 두 명을 반환합니다. 한 명 조회는 200과 해당 사용자를 반환합니다. Body에는 id, name, email만 있어야 합니다.

{"items":[{"id":1,"name":"Ada","email":"ada@example.com"},{"id":2,"name":"Lin","email":"lin@example.com"}]}

위 값은 새 DB의 예시입니다. 실제 id와 순서는 저장 이력에 따라 다를 수 있습니다. 브라우저에서 http://127.0.0.1:8000/docs를 열어 요청을 보내도 됩니다.

DB에서 바꾸고 API로 다시 읽기

psql에서 아래 명령을 실행합니다. UPDATE는 기존 row를 변경합니다. WHERE는 변경할 대상을 제한합니다. 먼저 SELECT로 대상을 확인합니다.

SELECT id, name, email FROM users WHERE email = 'ada@example.com';
UPDATE users SET name = 'Ada Updated' WHERE email = 'ada@example.com';

GET /users를 다시 요청합니다. name이 Ada Updated로 나오면 API가 DB에서 읽고 있다는 것을 확인한 것입니다. API server를 종료했다가 다시 켜도 변경한 값이 남는지 확인하세요.

이 예제는 로컬 dummy data 조회용이며 authentication이 없습니다. 실제 개인정보를 넣어 외부에 공개하지 않습니다. Password hash는 목록뿐 아니라 한 명 조회에서도 응답하지 않습니다.

확인: DB에 password_hash가 있는데 응답에는 왜 없을까요?

저장할 정보와 외부에 제공할 정보가 다르기 때문입니다. SELECT에서 id, name, email만 고릅니다. 비밀번호 검증 정보는 사용자 목록 화면에 필요하지 않습니다.

완료 기준

  • DB, table, row, column의 차이를 설명할 수 있습니다.
  • Users의 네 column과 제약을 확인했습니다.
  • 비밀번호 원문 없이 dummy data 세 명을 저장했습니다.
