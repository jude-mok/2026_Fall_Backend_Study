2026 Backend Study — 로그인까지 만드는 14주¶

한 학기 목표 Git에서 시작해 HTTP, REST API, 데이터베이스, 인증을 차례로 연결하고 마지막 주에 POST /signup, POST /login, GET /me가 동작하는 서버를 완성한다.

이 교재를 사용하는 법¶

  • 권장 실습 스택: Python 3.13 + FastAPI + Pydantic + PostgreSQL + SQLAlchemy + Docker Compose
  • 수업 시간: 주 1회 60분을 기준으로 개념 25분 → 시연 10분 → 실습 20분 → 회고 5분
  • 각자 본인 GitHub 계정에 backend-study 저장소를 새로 만들고, 모든 주차를 그 개인 저장소에서 이어서 진행한다. commit과 push는 본인 레포에서 한다.
  • Jude의 GitHub는 참고 답안으로 활용한다. 먼저 직접 구현하고 관련 코드를 비교한다. 공동 레포의 collaborator 등록이나 답안 레포로의 PR 제출은 필요하지 않다.
  • 2주차의 PR은 본인 레포의 작업 브랜치에서 본인 main으로 연다.
  • 각 장의 실습 체크박스를 완료하고, 배운 내용을 자기 말로 설명한다.
  • 명령과 코드의 암기보다 요청이 어디를 거쳐 상태를 바꾸는지 추적하는 데 집중한다.

학기 프로젝트의 최종 모습¶

sequenceDiagram actor U as User participant A as API Server participant DB as PostgreSQL U->>A: POST /signup (email, password) A->>A: validate + hash A->>DB: INSERT user DB-->>A: user id A-->>U: 201 Created U->>A: POST /login A->>DB: SELECT user by email DB-->>A: password_hash A->>A: verify + issue session/token A-->>U: credential U->>A: GET /me + credential A->>A: authenticate A->>DB: SELECT safe user fields A-->>U: 200 current user

완성 기준¶

  • 처음 보는 사람이 README만 읽고 서버와 DB를 실행할 수 있다.
  • 비밀번호 원문은 어디에도 저장하거나 로그로 남기지 않는다.
  • 중복 이메일, 잘못된 입력, 틀린 로그인, 인증 없는 /me가 예상한 상태 코드로 실패한다.
  • 성공 경로와 핵심 실패 경로에 자동화 테스트가 있다.
  • API 응답에 password_hash가 노출되지 않는다.
  • Git 기록이 작은 단위의 설명 가능한 커밋으로 구성된다.
