Week 08 — Backend Layers

7주차의 main.py를 역할별 파일로 분리하기 · 60분 실습

Layer는 관련된 책임을 모아 둔 코드의 구분입니다. 책임은 그 코드가 맡은 일입니다. 이번 수업에서는 데이터 형식, HTTP 처리, DB 조회·저장을 구별합니다. 폴더를 많이 만드는 것이 목표는 아닙니다.

Refactoring은 외부에서 보이는 동작을 유지하면서 내부 코드를 바꾸는 작업입니다. 이번에는 7주차의 URL, 입력 규칙, 응답 필드, status code를 유지합니다. 새 CRUD 기능이나 DB table은 추가하지 않습니다.

1. 분리 전 결과 기록

7주차 CRUD가 동작하는 코드로 시작합니다. .env.local과 database.py는 유지합니다. 먼저 다음 명령을 실행합니다.

uv sync
uv run pytest
uv run fastapi dev app/main.py

Swagger UI인 http://127.0.0.1:8000/docs를 엽니다. Swagger UI는 API 요청을 보내고 응답을 확인하는 웹 화면입니다. 자신의 실습 email로 POST를 실행합니다. 반환된 id를 기록하고 GET, PATCH, DELETE에 같은 id를 사용합니다.

요청유지할 결과
GET /users200, items 안에 id/name/email
POST /users201, 생성된 사용자
PATCH /users/{id}200, name만 변경
DELETE /users/{id}204, 빈 body
없는 id 조회404
중복 email 생성409
빈 name 입력422

2. 파일 이름보다 역할 먼저

구분맡은 일이번 예제
Model입력·출력 데이터의 형식과 검증 규칙name 길이, email 형식, 응답 필드
RouterHTTP 요청을 함수에 연결하고 응답을 결정POST /users, 201, 404, 409
RepositorySQL을 실행하고 조회·저장 결과를 반환INSERT, UPDATE, SELECT
Database 연결 함수접속 설정을 읽고 연결을 생성get_connection()
main.py앱을 만들고 Router를 등록FastAPI(), include_router()

이번 Model은 Pydantic Model입니다. Pydantic은 Python 데이터의 형식과 규칙을 검사하는 도구입니다. 이 Model은 DB table과 같은 것이 아닙니다. Model을 옮겨도 Supabase table은 바뀌지 않습니다.

Import는 다른 Python module의 이름을 현재 파일에서 사용하는 문법입니다. Module은 여기서 Python 파일 하나입니다. 예를 들어 from app.model.user import UserCreate는 app/model/user.py에 정의된 UserCreate를 가져옵니다.

확인: email 길이 규칙과 INSERT SQL은 같은 파일에 두어야 할까요?

이번 구조에서는 나눕니다. 입력 형식은 Model에 둡니다. DB 저장 SQL은 Repository에 둡니다. HTTP status code는 Router에서 결정합니다.

3. Model 먼저 분리

  1. app 안에 model 폴더를 만듭니다. 빈 __init__.py를 넣습니다. 이 파일은 폴더를 Python package로 명시합니다.
  2. app/model/user.py를 만듭니다.
  3. main.py의 UserName과 네 Model class를 아래 파일로 옮깁니다.
  4. main.py에서 해당 정의와 사용하지 않는 Pydantic import를 제거합니다.
  5. main.py에서 Model을 import합니다.
from typing import Annotated

from pydantic import BaseModel, ConfigDict, EmailStr, StringConstraints, field_validator

UserName = Annotated[
    str, StringConstraints(strip_whitespace=True, min_length=1, max_length=50)
]


class UserCreate(BaseModel):
    model_config = ConfigDict(extra="forbid")
    name: UserName
    email: EmailStr

    @field_validator("email")
    @classmethod
    def normalize_email(cls, value: str) -> str:
        return value.lower()


class UserNamePatch(BaseModel):
    model_config = ConfigDict(extra="forbid")
    name: UserName


class UserResponse(BaseModel):
    id: int
    name: str
    email: str


class UserListResponse(BaseModel):
    items: list[UserResponse]
from app.model.user import UserCreate, UserListResponse, UserNamePatch, UserResponse

서버를 다시 실행하고 POST와 GET을 확인합니다. 이름이 같은 class를 두 파일에 남기지 않습니다. 이 단계에서는 SQL과 endpoint가 아직 main.py에 있습니다.

4. Repository로 SQL 이동

Repository는 DB에 접근하는 함수를 모은 module입니다. Router는 필요한 값을 전달하고 Repository는 결과를 돌려줍니다. Repository는 이번 구조에서 HTTPException을 만들지 않습니다.

  1. app/repository 폴더와 빈 __init__.py를 만듭니다.
  2. user_repository.py에 아래 함수를 작성합니다.
  3. main.py의 각 endpoint에서 with get_connection() 블록을 제거합니다.
  4. 제거한 위치에서 해당 Repository 함수를 호출합니다.
from app.database import get_connection


def get_all_users(limit: int = 20):
    with get_connection() as conn:
        return conn.execute(
            "SELECT id, name, email FROM public.users ORDER BY id LIMIT %s",
            (limit,),
        ).fetchall()


def get_user_by_id(user_id: int):
    with get_connection() as conn:
        return conn.execute(
            "SELECT id, name, email FROM public.users WHERE id = %s",
            (user_id,),
        ).fetchone()


def create_user(name: str, email: str):
    with get_connection() as conn:
        return conn.execute(
            """INSERT INTO public.users (name, email, password_hash)
               VALUES (%s, %s, %s)
               RETURNING id, name, email""",
            (name, email, "!dummy-no-login"),
        ).fetchone()


def update_user_name(user_id: int, name: str):
    with get_connection() as conn:
        return conn.execute(
            """UPDATE public.users SET name = %s WHERE id = %s
               RETURNING id, name, email""",
            (name, user_id),
        ).fetchone()


def delete_user(user_id: int):
    with get_connection() as conn:
        return conn.execute(
            "DELETE FROM public.users WHERE id = %s RETURNING id",
            (user_id,),
        ).fetchone()

예를 들어 POST endpoint의 try 안에서 아래 호출을 사용합니다. 409로 변환하는 except는 main.py에 남깁니다.

from app.repository import user_repository

# create_user endpoint의 try 블록 안
return user_repository.create_user(body.name, str(body.email))

user_repository.create_user의 점은 module 안의 함수를 선택합니다. module 이름을 생략하면 현재 endpoint인 create_user를 다시 호출할 수 있습니다. 서로 다른 함수임을 명확하게 표시합니다.

GET 목록은 get_all_users(limit), GET 한 명은 get_user_by_id(user_id)를 호출합니다. PATCH는 update_user_name(user_id, body.name), DELETE는 delete_user(user_id)를 호출합니다. None을 404로 바꾸는 코드는 main.py에 남깁니다.

Repository의 with 블록은 그대로 옮깁니다. 정상 종료 시 commit하고, 오류 시 rollback하는 경계가 바뀌지 않습니다. 함수 안의 return도 with의 종료 처리를 거친 뒤 호출한 곳으로 돌아갑니다.

tests/test_users.py의 DB 대체 위치도 변경합니다. Mock은 실제 DB 대신 정해진 결과를 주는 테스트용 객체입니다. get_connection을 호출하는 곳이 main에서 user_repository로 바뀌었으므로 아래처럼 수정합니다. 기존 app.main의 app import는 유지합니다.

from app import database
from app.repository import user_repository

# db_connection fixture 안의 기존 monkeypatch.setattr 줄을 교체
monkeypatch.setattr(user_repository, "get_connection", lambda: manager)

uv run pytest를 실행합니다. 같은 API 테스트가 통과하는지 확인한 후 다음 단계로 갑니다.

5. Router 분리와 앱 등록

Router는 관련 endpoint를 묶는 객체입니다. APIRouter는 FastAPI가 제공하는 Router class입니다. app/router 폴더에 빈 __init__.py와 users.py를 만듭니다. main.py의 사용자 endpoint를 다음 코드로 옮깁니다.

from app.model.user import UserCreate, UserListResponse, UserNamePatch, UserResponse
from app.repository import user_repository
from fastapi import APIRouter, HTTPException, Query, Response
from psycopg.errors import UniqueViolation

router = APIRouter()


@router.get("/users", tags=["users"], response_model=UserListResponse)
def list_users(limit: int = Query(default=20, ge=1, le=100)):
    return {"items": user_repository.get_all_users(limit)}


@router.get("/users/{user_id}", tags=["users"], response_model=UserResponse)
def read_user(user_id: int):
    user = user_repository.get_user_by_id(user_id)
    if user is None:
        raise HTTPException(status_code=404, detail="User not found")
    return user


@router.post("/users", tags=["users"], status_code=201, response_model=UserResponse)
def create_user(body: UserCreate):
    try:
        return user_repository.create_user(body.name, str(body.email))
    except UniqueViolation as exc:
        if exc.diag.constraint_name != "users_email_key":
            raise
        raise HTTPException(status_code=409, detail="Email already exists") from exc


@router.patch("/users/{user_id}", tags=["users"], response_model=UserResponse)
def update_user(user_id: int, body: UserNamePatch):
    user = user_repository.update_user_name(user_id, body.name)
    if user is None:
        raise HTTPException(status_code=404, detail="User not found")
    return user


@router.delete(
    "/users/{user_id}", tags=["users"], status_code=204, response_class=Response
)
def delete_user(user_id: int):
    deleted = user_repository.delete_user(user_id)
    if deleted is None:
        raise HTTPException(status_code=404, detail="User not found")
    return Response(status_code=204)

@router.get 또는 @router.post는 바로 아래 함수를 요청 경로에 연결합니다. 기존 @app.get을 @router.get으로 바꿉니다. HTTPException, Query, Response와 UniqueViolation import도 사용하는 파일로 이동합니다.

main.py에는 다음 코드를 남깁니다. include_router는 users Router의 endpoint를 실제 앱에 등록합니다. 등록하지 않으면 /users 요청은 404가 됩니다.

from fastapi import FastAPI
from app.router.users import router as users_router

app = FastAPI(title="LikeLion Backend Study")
app.include_router(users_router)

@app.get("/", tags=["root"])
def read_root() -> dict[str, str]:
    return {"message": "Hello World"}

@app.get("/health", tags=["health"])
async def health() -> dict[str, str]:
    return {"status": "ok", "project_name": "2026 Fall Backend"}

as users_router는 가져온 router에 현재 파일에서 사용할 이름을 붙입니다. main.py는 Router를 import하고 Router는 Repository와 Model을 import합니다. Repository는 database.py를 import합니다. Repository에서 main.py를 import하지 않습니다.

app/
  main.py
  database.py
  model/__init__.py
  model/user.py
  router/__init__.py
  router/users.py
  repository/__init__.py
  repository/user_repository.py

6. 요청 하나를 끝까지 추적

GET /users/1을 예로 듭니다. 1은 조회할 사용자 id입니다.

  1. FastAPI가 등록된 Router의 read_user에 정수 1을 전달합니다.
  2. Router가 user_repository.get_user_by_id(1)을 호출합니다.
  3. Repository가 get_connection()으로 연결을 엽니다.
  4. Repository가 id가 1인 데이터를 조회하고 결과를 돌려줍니다.
  5. Router는 결과가 None이면 404를 반환합니다. 데이터가 있으면 UserResponse 형식으로 응답합니다.

분리 전과 같은 CRUD 요청과 실패 요청을 반복합니다. uv run pytest와 uv run ruff check app tests를 실행합니다. 테스트는 실제 DB 연결을 대신하므로 Swagger UI에서도 본인의 계정으로 확인합니다.

오류 확인
  • ModuleNotFoundError: 프로젝트 루트에서 실행했는지, 경로와 파일 이름이 맞는지 확인합니다.
  • /users만 404: main.py의 include_router를 확인합니다.
  • 함수가 반복 호출됨: endpoint에서 자기 자신을 호출했는지 확인합니다. module 이름을 붙입니다.
  • 테스트가 실제 DB에 접근함: Mock이 Repository의 get_connection을 교체하는지 확인합니다.

Service layer는 언제 추가할까?

Service layer는 업무 규칙이나 여러 작업의 순서를 모으는 곳입니다. 예를 들어 주문 생성 전에 재고 확인과 금액 계산이 필요하면 그 흐름을 담당할 수 있습니다. 현재 사용자 CRUD에는 그런 흐름이 적으므로 이번에는 추가하지 않습니다. 여러 DB 변경을 함께 확정해야 할 때는 transaction의 책임도 함께 설계해야 합니다.

완료 기준

  • CRUD URL과 응답이 7주차와 같습니다.
  • 입력·출력 정의는 Model에 있습니다.
  • SQL은 Repository에 있습니다.
  • HTTP status 처리는 Router에 있습니다.
  • main.py가 Router를 등록합니다.
  • 기존 테스트가 통과합니다.
  • 요청부터 SQL 실행과 응답까지 함수 호출 순서를 설명할 수 있습니다.
복습: 이름 길이를 바꿀 때와 정렬 순서를 바꿀 때 어느 파일을 수정할까?

이름 길이는 model/user.py의 UserName을 수정합니다. 정렬 순서는 repository/user_repository.py의 ORDER BY를 수정합니다. 사용자 없음의 HTTP 응답을 바꾸려면 router/users.py를 수정합니다.
